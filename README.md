# VTuber自動ショート動画抽出システム 仕様・設計書

## 1. システム概要
本システムは、長時間のVTuber配信アーカイブ動画（フルHD）から、見どころとなるシーン（ハイライト）を音声と視覚（AI）の両面から完全自動で抽出し、YouTube Shorts向けの縦型動画（9:16）として出力するクローズドツールです。

* **システム名称:** VTuber自動ショート動画抽出システム
* **利用者ターゲット:** 開発者自身の個人運用（クローズドツール）
* **主な特徴:**
  * 音量スパイクによる高速な一次スクリーニング
  * 大規模視覚言語モデル（VLM）による高精度な感情・文脈判定
  * YOLOv8を活用したアバターの動的トラッキング
  * GPUハードウェアエンコード（NVENC）による爆速レンダリング

## 2. 動作確認済み環境
本システムは、以下の環境において正常に動作することが確認されています。

* **OS:** Windows
* **CPU:** x86_64アーキテクチャ（マルチコア推奨）
* **GPU:** NVIDIA GeForce RTX 5070 Ti (VRAM 16GB) または同等以上のNVIDIA GPU
* **言語:** Python 3.13 (64bit)
* **主要ライブラリ:**
  * PyTorch (CUDA 12.8対応版)
  * Transformers, accelerate, qwen-vl-utils (Hugging Face)
  * Ultralytics (YOLOv8)
  * OpenCV (opencv-python), Librosa
* **外部依存ツール:** FFmpeg (バイナリ実行ファイルとして同梱)

## 3. 運用仕様（入出力・パラメータ設定）

### 3.1. 入力仕様
* **ソース動画フォーマット:** MP4形式
* **想定解像度・フレームレート:** 1920x1080 (フルHD) / 60fps
* **運用方法:** * 【現状】スクリプト内の変数（`VIDEO_PATH`）にファイル名を直接記述し、都度書き換えて実行する。
  * 【今後の予定】動画のダウンロードを自動で行うコードを組み込み、手動でのファイル指定や書き換えを不要にする。

### 3.2. 出力仕様
* **出力フォーマット:** MP4形式 (H.264, AAC)
* **ターゲット媒体:** YouTube Shorts
* **解像度・アスペクト比:** 1080x1920 (9:16)
* **画面レイアウト:**
  * 上部 (1080x1080): ゲーム等のメイン画面（中央クロップ）
  * 下部 (1080x840): アバターの顔枠（YOLOによる自動追従・クロップ）

### 3.3. パラメータ設定値
各種パラメータは、現状スクリプト内にデフォルトの固定値として定義されています。
（※ 今後のアップデートにて、外部から柔軟に変更できる仕様へ移行予定）
* **アバター初期座標 (ROI):** `(1420, 220, 462, 360)`
* **音声検知しきい値:** 平均音量 + 2.5 × 標準偏差 (`threshold_k=2.5`)
* **感情判定の合格基準:** `["大爆笑", "絶叫", "驚愕"]` のいずれか

## 4. システムアーキテクチャ・処理フロー

処理は大きく3つのフェーズに分かれ、後続のフェーズに進むほど高度（高負荷）な処理へ移行するパイプライン構造を採用しています。

### 4.1. 【PHASE 1】音声エネルギー解析 (Audio Scan)
* **音声の読み込み:** `librosa` を使用し、処理速度向上のため 16kHz / モノラル にダウンサンプリングして読み込む。
* **RMS（二乗平均平方根）計算:** フレーム長2048、ホップ長512でエネルギー推移を計算。
* **しきい値判定:** 動画全体の平均RMSと標準偏差から動的にしきい値（`mean + 2.5 * std`）を設定。
* **セグメント結合 (マージ処理):**
  * 近接するスパイク（3秒以内）は1つのシーンとして結合。
  * 前後にマージン（前5秒、後15秒）を付与し、カット時の不自然さを防ぐ。

### 4.2. 【PHASE 2】モーション解析 ＆ VLM表情判定 (Vision Filter)
* **ステップ1：モーション解析 (オプティカルフロー)**
  * 指定されたROI（アバター位置）に対し、`cv2.calcOpticalFlowFarneback` を実行（3フレーム間隔で間引き処理）。
  * 動きのベクトル量（Magnitude）を算出し、ピーク時間を特定。動きの最大値が規定値（`1.2`）未満のものは除外。
* **ステップ2：VLM（視覚言語モデル）による表情判定**
  * モデル: `Qwen/Qwen2-VL-7B-Instruct` (bfloat16精度でVRAMにロード)
  * 解析: ピーク時間の画像を抽出し、モデルに以下をプロンプトとして入力。
    > 「これはVTuberのワイプ画面です。アバターの表情のコンテキストを解析し、[大爆笑, 絶叫, 驚愕, 通常・その他] の中から最も適切なものを1つだけ返してください。」
  * フィルタリング: 出力が「大爆笑」「絶叫」「驚愕」のいずれかの場合のみ、最終的なショート動画候補として承認。
* **リソース管理:** フェーズ完了後、`torch.cuda.empty_cache()` および `gc.collect()` を呼び出し、VLMが占有したVRAM（約14GB）を完全に解放してフェーズ3に備える。

### 4.3. 【PHASE 3】動的トラッキング ＆ 動画エンコード (Dynamic Tracking & Render)
* **動的ROIトラッキング (`detect_avatar_roi_yolo`)**
  * モデル: 最高精度のアニメ顔検出モデル `yolov8x6_animeface.pt`
  * 処理: 対象シーンの開始後1秒時点のフレームを推論し、アバターのバウンディングボックスを取得。
  * マージン計算: 顔の周囲を十分に含むよう、係数（2.2倍）を掛けてクロップ領域（縦横比 1080:840）を動的に算出。認識失敗時はデフォルトのROIへフォールバック。
* **動画合成・レンダリング (`FFmpeg Filter Complex`)**
  * **[main]:** 元動画の中心付近（1080x1080）をゲーム画面としてクロップ。
  * **[wipe]:** YOLOで算出したROI領域をクロップし、1080x840にリサイズ。
  * **[outv]:** `vstack` を用いて [main] と [wipe] を縦に結合し、1080x1920 の画面を生成。
* **エンコード設定**
  * ビデオコーデック: `h264_nvenc`（RTX 5070 Ti のハードウェアエンコーダを使用）
  * プリセット: `p6`（High Quality）、チューニング: `hq`
  * ビットレート: 映像 14Mbps / 音声 192k (AAC)
  * 出力先: `./output_shorts/short_{id}_{emotion}_motion{motion_score}.mp4`
